## 一、唯一正确性口径：甲路径

同一 `old_key` 在同一生效版本下有 N 个目标 `new_key`（N ≥ 2）时，完备落库只允许走甲：

> **甲：每个目标新键各插一条正式行；任一目标缺失，则整笔扇出事务回滚，正式区零增。**

执行定义（不得拆成两段提交）：

1. 以映射册（`mappings`）在生效版本下的全部目标为准，目标集合先去重。
2. 同一事务内：每个目标插正式行；每个目标插别名行；按实际落库结果写扇出回执。
3. 提交前复核：`正式目标集合 == 别名目标集合 == 映射册目标集合`。任一不等或任一插入失败，整笔回滚。
4. 回执中的目标数、正式行数、别名行数只能来自本事务内的实际计数，不得用请求参数或页面常量拼装。
5. 正式行、别名行、回执三者与映射册同事务提交；不存在“回执先绿、别名后补”。

## 二、乙路径排除

乙路径（只落主正式行、其余进别名；别名失败回滚主正式与别名）**明确排除**，不得与甲混用：

- 不在正式区之外只留“主新键”。
- 不实现“主正式 + 别名”双轨。
- 任何代码分支出现“仅主键落正式”即判偏离。

## 三、并发锁

- 同一 `old_key` 的扇出写路径必须先占锁（`fanout_locks`，`old_key` 主键，带 holder / acquired_at）。
- 后到者不得排队重试成成功，须立即判争用：HTTP 409，并在冲突队列记 `reason=争用`、`status=争用`。
- 锁在成功、失败、回滚后均须释放；超过 TTL 的陈旧锁可回收。

## 四、五处同态

正式区 `formal_entities`、别名表 `aliases`、映射册 `mappings`、互证页 `reconcile`、扇出回执 `fanout_receipts` 必须同态：

- 对同一 `(version, old_key)`：映射目标集合 == 正式目标集合 == 别名目标集合 == 回执计数。
- 互证页只读库内事实，不得由页面拼接推断“齐全”。
- 只改页面文案、进度条或拼接不视为修复，判失败。

## 五、测试顺序（不得跳步）

1. 先复现：旧路径下回执 HTTP 200 且返回主新键，正式区仅 1 行，别名表为空/不存在。
2. 落“扇出失败测”：多目标全量落库 + 注入别名写失败 → 整笔回滚、正式零增。此步必须见红。
3. 落“抢扇争用失败测”：同旧键已有持有锁，后到 → 409 + 争用记录。此步必须见红。
4. 两条红测齐备后，才准修改扇出写路径。
5. 全绿验收：目标数 == 别名数 == 正式数 == 回执计数。

## 六、偏离处理

- 运行期若切断口径被改为非甲：拒绝写入，冲突队列记 `reason=扇出偏了`、`status=拒绝`，返回 409。
- 禁止无复现直接改进度条；禁止跳过失败测先改实现。
